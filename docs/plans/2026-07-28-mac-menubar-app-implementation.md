# Mac Menu Bar App Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** A signed native macOS menu bar app that reads Claude Code's credential, fetches usage, renders the 64x32 animated frame in-process, and pushes it to a tronbyt-server — replacing the two launchd agents and the Docker deployment entirely.

**Architecture:** Single process, no HTTP server, no IPC. `UsageClient` is the one source of truth; the menu bar view and the frame renderer both read its published state, so one fetch feeds both. Rendering is Core Graphics into an RGBA buffer, encoded to animated WebP through libwebp's `WebPAnimEncoder` (macOS cannot encode WebP itself — verified).

**Tech Stack:** Swift 6.3, SwiftUI `MenuBarExtra`, Core Graphics, `libwebp-Xcode` via SwiftPM, XcodeGen for a text-based project definition, `xcodebuild` for builds, XCTest.

**Design doc:** `docs/plans/2026-07-28-mac-menubar-app-design.md` — read it first. It records the measurements behind these decisions.

```swift
import XCTest
@testable import ClaudeUsage

final class WebPAnimationTests: XCTestCase {
    /// Two 64x32 solid-colour frames, 2500ms apart, must encode to a non-trivial
    /// animated WebP whose bytes carry the WebP + animation chunk markers.
    func testEncodesTwoFrameAnimation() throws {
        let red = [UInt8](repeating: 0, count: 64 * 32 * 4).enumerated().map { i, _ in
            i % 4 == 0 ? UInt8(255) : (i % 4 == 3 ? UInt8(255) : UInt8(0))
        }
        let blue = [UInt8](repeating: 0, count: 64 * 32 * 4).enumerated().map { i, _ in
            i % 4 == 2 ? UInt8(255) : (i % 4 == 3 ? UInt8(255) : UInt8(0))
        }

        let data = try WebPAnimation.encode(
            frames: [red, blue], width: 64, height: 32, frameDurationMs: 2500
        )

        XCTAssertGreaterThan(data.count, 100, "suspiciously small output")
        // RIFF container: "RIFF" ....  "WEBP"
        XCTAssertEqual(Array(data[0..<4]), Array("RIFF".utf8))
        XCTAssertEqual(Array(data[8..<12]), Array("WEBP".utf8))
        // Animated WebP carries a VP8X extended-format chunk and an ANIM chunk.
        XCTAssertTrue(contains(data, "VP8X"), "not an extended-format WebP")
        XCTAssertTrue(contains(data, "ANIM"), "no animation chunk — not animated")
    }

    private func contains(_ data: Data, _ marker: String) -> Bool {
        data.range(of: Data(marker.utf8)) != nil
    }
}
```

**Step 3: Implement the encoder**

Confirm exact symbol names against the vendored headers before writing this —
`find ~/Library/Developer/Xcode/DerivedData -name mux.h -path '*webp*'` — and read
`WebPAnimEncoderOptionsInit`, `WebPAnimEncoderNew`, `WebPAnimEncoderAdd`,
`WebPAnimEncoderAssemble`. The shape below is correct as of libwebp 1.5 but verify
rather than trust it.

```swift
// mac/Sources/ClaudeUsage/WebPAnimation.swift
import Foundation
import libwebp

enum WebPAnimationError: Error {
    case optionsInitFailed
    case encoderAllocFailed
    case pictureInitFailed
    case pictureImportFailed
    case addFrameFailed(Int)
    case assembleFailed
}

struct WebPAnimation {
    /// Encode RGBA frames into an animated WebP. Each frame must be
    /// width*height*4 bytes.
    static func encode(frames: [[UInt8]], width: Int, height: Int,
                       frameDurationMs: Int) throws -> Data {
        var options = WebPAnimEncoderOptions()
        guard WebPAnimEncoderOptionsInit(&options) != 0 else {
            throw WebPAnimationError.optionsInitFailed
        }
        options.anim_params.loop_count = 0   // loop forever

        guard let encoder = WebPAnimEncoderNew(Int32(width), Int32(height), &options) else {
            throw WebPAnimationError.encoderAllocFailed
        }
        defer { WebPAnimEncoderDelete(encoder) }

        var config = WebPConfig()
        guard WebPConfigInit(&config) != 0 else { throw WebPAnimationError.optionsInitFailed }
        config.lossless = 1              // 64x32 pixel art: lossless is small and exact

        for (index, frame) in frames.enumerated() {
            var picture = WebPPicture()
            guard WebPPictureInit(&picture) != 0 else {
                throw WebPAnimationError.pictureInitFailed
            }
            defer { WebPPictureFree(&picture) }
            picture.width = Int32(width)
            picture.height = Int32(height)
            picture.use_argb = 1

            let imported = frame.withUnsafeBufferPointer { buf in
                WebPPictureImportRGBA(&picture, buf.baseAddress, Int32(width * 4))
            }
            guard imported != 0 else { throw WebPAnimationError.pictureImportFailed }

            guard WebPAnimEncoderAdd(encoder, &picture,
                                     Int32(index * frameDurationMs), &config) != 0 else {
                throw WebPAnimationError.addFrameFailed(index)
            }
        }
        // A final null frame stamps the end timestamp so the last frame has duration.
        guard WebPAnimEncoderAdd(encoder, nil,
                                 Int32(frames.count * frameDurationMs), nil) != 0 else {
            throw WebPAnimationError.addFrameFailed(frames.count)
        }

        var output = WebPData()
        WebPDataInit(&output)
        defer { WebPDataClear(&output) }
        guard WebPAnimEncoderAssemble(encoder, &output) != 0 else {
            throw WebPAnimationError.assembleFailed
        }
        return Data(bytes: output.bytes, count: output.size)
    }
}
```

## Task 7: Frame renderer — glyph font and geometry

**Scope correction (2026-07-29):** this task also needs a bitmap font, which the
plan originally missed. The frame contains text (`48`, `5H`, `AS OF 15:44`) and the
current display gets it from pixlet's built-in `tom-thumb`. Swift has no
equivalent, and Core Graphics cannot substitute: any real font rendered 5 pixels
tall is illegible regardless of antialiasing. So a 3x5 glyph set is authored here —
digits, A-Z, `%`, `:`, `(`, `)`, `-`, space. Written from scratch rather than
copying tom-thumb's data, whose licensing has not been checked.

3 pixels wide plus 1 of spacing gives a 4px advance, which is where the design
doc's "~16 characters across 64px" comes from.

**Files:**
- Create: `mac/Sources/ClaudeUsage/PixelFont.swift`
- Create: `mac/Sources/ClaudeUsage/Canvas.swift`
- Create: `mac/Sources/ClaudeUsage/FrameRenderer.swift`
- Create: `mac/Tests/ClaudeUsageTests/PixelFontTests.swift`
- Create: `mac/Tests/ClaudeUsageTests/FrameRendererTests.swift`

Port `ring_pixels`, `pct_color`, and `countdown_text` from `claude_usage.star`.
Draw into a `CGContext` over an RGBA buffer, 64x32, no antialiasing (pixel art —
`context.setShouldAntialias(false)`).

**Tests:**
- `pct_color`: 49 → green, 50 → amber, 80 → red (same thresholds as the star).
- A 0% ring draws only track pixels; 100% draws no track pixels.
- Output buffer is exactly `64*32*4` bytes.
- Grey (dead) variant emits **no** green/amber/red pixels at all — scan the buffer
  and assert it. This is the test that keeps the staleness promise honest.
- `countdown_text`: 90 min → `1H30M`; 25 h → `1D`; negative → `0H00M`.

## Task 12: Signing, notarization, and cutover

**Unblocked 2026-07-29:** `Developer ID Application: Taylor Bird (UFCDGSKCXB)`
is installed and `security find-identity -v -p codesigning` reports 1 valid
identity. Team ID `UFCDGSKCXB`. A Developer ID *Installer* cert also exists, unused
— it would only matter if we ever ship a `.pkg` rather than a zipped `.app`.

**Note:** builds are signed with the real Developer ID from Task 1 onward, not
ad-hoc. This is deliberate: the macOS Keychain consent grant for Claude Code's
credential item (Task 5) is bound to the requesting app's signing identity, so
developing under ad-hoc and re-signing later would silently invalidate the grant
and re-prompt. Signing consistently from the start means you approve it once.

**Steps:**
1. Archive and export; sign with hardened runtime and a timestamp.
3. Notarize with `xcrun notarytool submit --wait`, then `xcrun stapler staple`.
4. Verify: `codesign -dv --verbose=4` and `spctl -a -vvv` on the exported app.
5. Install to `/Applications`, add to Login Items.
6. Run it alongside nothing else and confirm the device updates.
7. Cut over:
   ```bash
   launchctl unload ~/Library/LaunchAgents/com.tbird.claude-usage-serve.plist
   launchctl unload ~/Library/LaunchAgents/com.tbird.claude-usage-push.plist
   rm ~/Library/LaunchAgents/com.tbird.claude-usage-{serve,push}.plist
   ```
8. Delete the dead `claude_usage` app registration in the tronbyt web UI.
9. **Rotate the tronbyt API key** — it has been in cleartext in a plist and was
   surfaced in a session transcript.
10. Retire `docker/` and `scripts/`; keep `claude_usage.star` marked as the visual
    reference the renderer was ported from, no longer live.

**Do not delete the launchd plists until the app has run correctly for a day.**
They are the working fallback.

## Risks

| Risk | Mitigation |
|---|---|
| `WebPAnimEncoder` unreachable or output rejected | Task 2 is a spike that fails fast, before any dependent work |
| Keychain consent prompt is disruptive or re-prompts | Fallback documented in the design doc: a settings field to paste a credential |
| Core Graphics ring differs subtly from pixlet's output | Golden-image test plus eyeballing on the real device |
| No signing identity | Ad-hoc signing carries all development; Task 12 is isolated at the end |
| `expiresAt` is milliseconds | Called out explicitly in Task 5; a unit test pins it |
